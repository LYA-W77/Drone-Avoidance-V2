### Bug #1：VS 版本不兼容导致编译失败

- **时间**：2026.05.29
- **现象**：双击 `.uproject` 文件，提示需要 VS 2019 工具集，但本机安装的是 VS 2022
- **排查过程**：
  1. 检查项目配置文件，发现强制要求 `v142` 工具集
  2. 尝试在 VS 2022 中直接打开，仍报工具集缺失
- **根因**：项目配置文件写死了 VS 2019 工具集，VS 2022 默认不包含
- **解决方案**：
  1. 安装 VS 2019 生成工具（Build Tools），仅安装编译工具链，不安装完整 IDE
  2. 在 VS 2022 中打开项目，右键项目 → 属性 → 平台工具集 → 手动选择 `v142`
- **关键认知**：编译器、工具链和 IDE 是可分离的。无需改变默认打开方式，手动指定即可兼容。

## 第二阶段：场景配置与首次飞行

### Bug #4：EXCEPTION_ACCESS_VIOLATION 崩溃

- **时间**：2026.05.30
- **现象**：运行 UE4 编辑器后立即崩溃，报 `EXCEPTION_ACCESS_VIOLATION`
- **排查过程**：
  1. 检查 `settings.json`，发现 `VehicleType` 被设置为 `PX4Multirotor`
  2. 查看 AirSim 文档，`PX4Multirotor` 需要搭配 PX4 SITL 飞控硬件仿真环境
- **根因**：`settings.json` 中 `VehicleType` 配置错误。`PX4Multirotor` 需搭配 PX4 SITL（软件在环仿真），本机未安装 PX4
- **解决方案**：
  1. 将 `VehicleType` 改为 AirSim 内置轻量飞控 `SimpleFlight`
  2. 将 `AutoCreate` 设为 `true`
- **关键教训**：`SimpleFlight` 无需外部依赖，适合快速验证。

### Bug #5：新关卡中无人机失控

## 第三阶段：自主避障算法开发与迭代

### Bug #7：深度图数据恒为 1.0 米

- **时间**：2026.05.31
- **现象**：使用 `airsim.ImageType.DepthPlanar` 获取深度图，数据全部为 1.0 米，无法感知真实距离
- **排查过程**：
  1. 检查深度图渲染配置，发现缺少必要的后处理设置
  2. 尝试不同 API 调用方式，结果相同
- **根因**：AirSim 深度图依赖渲染配置，需在 `settings.json` 中开启深度图渲染，且 UE4 场景需正确配置
- **解决方案**：放弃深度图方案，改用距离传感器
- **关键教训**：在算法验证阶段，单点距离传感器比深度图更简单、准确、实时性好。

### Bug #8：距离传感器读数恒为 30 米

- **时间**：2026.05.31
- **现象**：添加距离传感器后，所有读数均为 30.0 米（无效值）
- **排查过程**：
  1. 检查代码中的传感器名称：`sensor_names = ["MyDistanceLeftLarge", "MyDistanceLeftSmall", "MyDistanceCenter", "MyDistanceRightSmall", "MyDistanceRightLarge"]`
  2. 检查 `settings.json`，发现传感器名称不匹配
- **根因**：代码中的传感器名称与 `settings.json` 配置不一致
- **解决方案**：
  1. 统一代码和配置中的传感器名称
  2. 添加 5 个分布于前方 ±30° 的传感器
  3. 名称匹配后，读数恢复正常
- **关键教训**：传感器名称必须完全匹配，包括大小写。

### Bug #9：无人机原地打转、旋转失控

- **时间**：2026.05.31
- **现象**：无人机面对障碍物时持续旋转，无法向前飞行
- **排查过程**：
  1. 检查控制逻辑，发现每帧累加绝对偏航角：`new_yaw = current_yaw + turn_angle`
  2. 检查 `moveByVelocityZAsync` 调用，垂直速度参数被误用
- **根因**：
  1. 偏航角累加会导致无人机不断自旋，而非绕行
  2. 运动方向与机头朝向矛盾
- **解决方案**：
  1. 放弃通过改变偏航角转向的思路
  2. 改用 `moveByVelocityBodyFrameAsync` 发送机体系速度指令
  3. 让无人机通过侧向平移自然绕行，不干预偏航
- **关键认知**：在未知环境中，速度指令优于偏航角控制。

### Bug #10：死胡同无限循环（局部极小值）

- **时间**：2026.05.31
- **现象**：在狭窄环境中，无人机陷入死循环，不断原地旋转
- **排查过程**：分析决策逻辑，发现单纯基于当前帧距离的避障方法无法应对“三面环墙”的场景
- **根因**：纯反应式系统缺乏“记忆”，无法识别重复状态，会反复尝试相同动作
- **解决方案**：
  1. 引入连续死胡同计数器
  2. 连续触发死胡同 → 先旋转试探
  3. 超过阈值 → 调用 `force_escape()` 强制后退 + 上升
- **关键教训**：纯反应式系统必须考虑局部极小值，增加计数器与逐步升级策略可有效避免死锁。

### Bug #11：避障响应迟钝（撞树）

- **时间**：2026.05.31
- **现象**：传感器数据正常，但无人机仍撞上障碍物
- **排查过程**：检查避障逻辑，发现安全距离阈值为 3.0 米，但无人机以 3.0 m/s 速度飞行，留给决策的时间不足 1 秒
- **根因**：安全距离阈值设置过小，侧向速度倍数过低（0.8），绕行动作不够果断
- **解决方案**：
  1. 将 `SAFE_DISTANCE` 从 3.0 调整为 5.0 米
  2. 将紧急避障时侧向速度倍数从 0.8 调至 1.2
- **关键教训**：阈值设置需综合考虑飞行速度与传感器响应时间。

### Bug #12：起飞后未按预期转向目标

- **时间**：2026.05.31
- **现象**：起飞后无人机直飞，未转向左转90°方向的目标点
- **排查过程**：检查目标计算逻辑，发现目标坐标在起飞前就已计算，但起飞后的实际偏航角与初始值有偏差
- **根因**：目标坐标基于起飞前的偏航角计算，起飞后无人机可能因姿态初始化而产生微小偏航偏移
- **解决方案**：
  1. 起飞后在 `connect_and_takeoff` 后显式调用 `rotate_in_place(90)` 原地左转
  2. 基于旋转后的偏航角动态计算目标坐标
- **关键教训**：初始化顺序很重要——先稳定姿态，再设定目标。

### Bug #14：模块拆分后导入路径报错

- **时间**：2026.07
- **现象**：将单体脚本拆分为 `core/`、`perception/`、`decision/`、`scripts/` 后，运行 `run_keyboard_control.py` 报 `ModuleNotFoundError`
  
- **排查过程**：
  1. 检查 Python 的模块搜索路径（`sys.path`）
  2. 发现 `scripts/` 子目录不在 Python 搜索路径内

- **根因**：Python 默认只搜索当前目录和系统路径，不会自动识别 `src/` 下的子模块

- **解决方案**：
  1. 在 `run_keyboard_control.py` 顶部添加以下代码：
  ```python
  import sys
  import os
  # 将项目根目录添加到 Python 搜索路径
  sys.path.append(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
  ```
  2. 然后使用相对导入：
   ```python
   from core.flight_controller import FlightController
   from perception.sensor_fusion import SensorFusion
   from decision.advanced_avoidance import AdvancedAvoidance
  ```
 

### Bug #15：激光雷达点云处理延迟

- **时间**：2026.07
- **现象**：启用激光雷达后，控制循环从 0.25s 延迟到 0.6s，无人机反应变慢
- **排查过程**：
  1. 添加时间戳测量 `get_lidar_distances` 执行时间
  2. 发现点云解析和扇区划分占用大量 CPU
- **根因**：激光雷达点云量过大（每帧约 5000+ 点），逐点计算角度和距离耗时
- **解决方案**：
  1. 降低点云采样率：在 `settings.json` 中设置 `NumberOfChannels: 16`
  2. 提前过滤：剔除后方点（`x_body < 0`）和地面点（`z > 0`）
  3. 仅在 `verbose=True` 时存储点云用于可视化
- **关键教训**：传感器数据需要预处理优化，避免阻塞控制循环。

## 第五阶段：算法升级——加权间隙避障（WGA）

### Bug #16：人工势场法（APF）导致局部极小值

- **时间**：2026.07
- **现象**：在喷泉场景中，无人机原地转圈，无法脱困
- **根因**：APF 的“引力”和“斥力”在特定位置相互抵消，产生局部极小值
- **解决方案**：淘汰 APF，改用加权间隙避障（WGA）算法
- **关键教训**：理论研究平滑，但工程调参困难，局部极小值难以避免。

---

### Bug #17：WGA 侧向速度方向错误

- **时间**：2026.07
- **现象**：目标在前方，无人机却向右后方移动
- **排查过程**：
  1. 打印 `target_angle`（目标相对机头的角度）
  2. 检查速度合成公式
- **根因**：`vy_target = -cos(target_angle)` 符号错误，应为 `vy_target = sin(target_angle)`
- **解决方案**：修正符号，目标方向权重 `alpha = 0.6`
- **关键认知**：坐标变换符号错误是避障算法最常见的 Bug，务必逐一验证。

### Bug #18：正前方 < 3m 时转向反应慢

- **时间**：2026.07
- **现象**：正前方 2.5 米有障碍，飞机仍在缓慢前进，没有大角度转向
- **根因**：`decide_action` 中正前方 < 2m 才触发强制转向，阈值太小
- **解决方案**：
  1. 增加阈值：正前方 < 3m 时强制侧向转向
  2. 增大转向系数：`vy_base = 1.5`（原 0.8）
- **关键教训**：避障算法的阈值必须通过实测反复调整，不能靠理论计算。

## 第六阶段：算法调参与稳定飞行（2026.07）

### Bug #19：直线飞行大幅振荡

- **时间**：2026.07
- **现象**：无障碍物时，飞机沿直线飞行，但左右晃动明显
- **排查过程**：
  1. 打印侧向速度指令，发现传感器噪声导致速度指令跳变
  2. 检查转向增益 `gain` 过高（1.2）
- **根因**：
  1. 转向增益过高，放大了微小的偏差
  2. 缺少低通滤波，传感器噪声直接作用于控制
- **解决方案**：
  1. 降低转向增益：`gain` 从 1.2 → 0.3
  2. 增加一阶低通滤波：`vy_filtered = vy_filtered * 0.3 + vy_raw * 0.7`
- **关键教训**：增益和滤波是控制算法最关键的调参维度，需要反复迭代。

---

### Bug #20：目标方向权重修正

- **时间**：2026.07
- **现象**：避障动作正确，但目标方向拉回作用不明显，飞机偏离航线
- **根因**：`vy_target` 与 `vy_obstacle` 融合时权重分配不合理
- **解决方案**：
  1. 修正 `vy_target` 计算公式：目标方向权重 `alpha = 0.6`
  2. 最终侧向速度：`vy = alpha * vy_target + (1-alpha) * vy_obstacle`
- **关键认知**：权重分配需要反复实测调优，理论值仅作为初始参考。

## ✅ 参数固化（最终调试结果）

经过 20+ 次飞行测试，确定最终参数：

```python
safe_distance = 5.0        # 安全距离
cruise_speed = 3.0         # 巡航速度
alpha = 0.6                # 目标方向权重
gain = 0.3                 # 转向增益
filter_alpha = 0.3         # 低通滤波系数
min_speed = 0.8            # 最低前向速度
target_distance = 100.0    # 目标距离
takeoff_left_turn = False  # 取消起飞后左转
```

## 💡 核心感悟

### 1. 仿真环境的严谨性至关重要

传感器命名、配置缺失等微小细节会引发令人困惑的行为，必须优先排查仿真设置。

### 2. 设计冗余与逃生出口

纯反应式系统必须考虑局部极小值（死胡同），增加计数器与逐步升级策略可有效避免死锁。

### 3. 速度指令优于偏航角控制

在未知环境中，让无人机通过速度矢量自然绕行，远比精确控制机头方向更稳定。

### 4. 调参是科学也是艺术

理论计算只能给出初始值，最终参数必须通过实测反复迭代。

### 5. 工程文档是最好的复盘工具
